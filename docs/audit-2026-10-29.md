# Code audit, 29 October 2026

Measured on `main` at v36 (`87cdcc5`). Counts are lines, without `public/vendor`.

## Size

The app is 38,063 lines over 72 files: `public` 20,572 and `src` 17,520, with `test` 12,734 and
`scripts` 2,199 beside it. Nine files are over 1,000 lines and hold 17,579 of them (46%):

| File | Lines | What is in it |
|---|---:|---|
| `public/app.js` | 3,003 | Shell and routing, the Today lists, the Plan page and its forms, sheets, Coach, Review, Settings, push, the lock screen, Face ID, every click on those pages (one 480-line `handleAction`), keyboard and visibility handling, the update check, boot |
| `public/food.js` | 2,733 | The diary, the SVG drawings (rings, bars), 20 sheet bodies, recipes, saved meals, the coverage report, Trends (17 cards), the click handler (360 lines), forms, search-as-you-type |
| `public/app.css` | 2,521 | Tokens and base, then every page but Food, Calendar and Plan: Today, sheets, Coach, Review, Settings, Health, Goals, navigation, the lock screen |
| `src/food.js` | 2,119 | Food schema, records, search, the diary, fills, grades, history and insights for Trends, saved meals, recipes, batches, plans, the coverage report, the API |
| `src/calendar.js` | 1,963 | An iCalendar parser, a 300-line Windows time-zone table, RRULE expansion, feed fetching, feeds, VLE deadlines, Oath's own events, the read side, the API |
| `public/food.css` | 1,598 | The Food palette and every Food screen, Trends, real burn, Food and body, the scanner, fast logging |

## What mixes unrelated parts

- **`public/app.js`** is the main problem. Today, Coach, Review, Settings, push, the lock screen and
  Face ID have nothing to do with each other, but any change to one of them means loading all 3,000
  lines. `handleAction` is one `if`/`else` chain of about 70 actions across six pages.
- **`public/food.js`**: the drawings are pure functions with no state; Trends is a page of its own;
  the sheet bodies are a third of the file.
- **`src/calendar.js`**: the iCalendar parser and RRULE expansion (about 870 lines) are pure functions
  with no database, next to the feed and event code that uses them.
- **`src/health.js`**: the parsers for two export formats (about 480 lines) are pure, next to storage
  and the API.
- **`src/food.js`**: recipes, batches, plans and saved meals (about 540 lines) and the Trends history
  and insights (about 280) are separate features in the diary's module.
- **`public/app.css`**: one file styles nine pages; Food, Calendar and Plan already have their own.

## Dead code

Checked by a script (every top-level name and export counted across `public`, `src`, `test` and
`scripts`, every CSS class searched for in the JavaScript and HTML), then by hand for names built at
run time (`u-${heat}`, `page-${route}` and so on).

Never used anywhere:

- `public/food-tags.js`: export `groupTags`
- `src/auth.js`: export `loginLocked`
- `src/calendar.js`: `minutesOf`
- `src/rules.js`: export `previousOccurrence`
- `src/time.js`: export `nowIn`

CSS nothing draws any more:

- Sleep, which left the app in `088171e`: `.c-sleep` (with the `--c-sleep` tokens), `.stages`, `.st-deep`,
  `.st-core`, `.st-rem`, `.st-awake`, `.stages-legend`, `.stages-label` in `app.css`
- `.fleft-row`, `.fleft-v` in `food.css`; `.gh-links` in `calendar.css`

Not dead, but wider than needed: 112 exports are used only inside their own module. Dropping the
`export` word changes nothing and touches dozens of files, so they are left.

## Duplication

- `public/today.js` declares its own `reduced` and `num`, identical to the ones `ui.js` exports.
- `public/food-energy.js` copies `uid`, `nextId` and `hatchDef` from `food.js` (the SVG pattern ids).
- `public/food-next.js` copies `enc`, `uuid` and `store` from `food.js`; `food-usual.js` copies `cap`.
- `plural` is written out in `plan.js` and `food-energy.js`, and `num` in eight server modules.
  The server copies are left: each is one line and a shared helper would tie unrelated modules.

## Plan, in order

Each step is one behaviour-neutral commit on `v37/refactor`, checked with `node --check`, the import
checker, the full test suite and screenshots against `main`.

1. **Dead code out**, from the list above.
2. **`public/app.js` split** along its sections, each a module with `initX(ctx)` and exported view and
   click functions, as `today.js` and `plan.js` already are:
   - `today-list.js`: Today's lists, the Now panel, the schedule and the page itself
   - `plan.js` takes the Plan page and the habit and task forms it already sits beside
   - `coach.js`: the Coach page and sending to the coach
   - `review.js`: the Review page
   - `settings.js`: Settings and push
   - `lock.js`: the way in, the lock screen and Face ID
   - `update.js`: staying on the newest version (`BUILD` stays in `app.js`, where the test reads it)
   - `handleAction` splits into a click function per module; `app.js` keeps the shell, routing,
     loading, the sheets frame and boot.
3. **`public/food.js` split**: `food-draw.js` (rings, bars, the shared SVG helpers, so `food-energy.js`
   stops copying them), `food-trends.js` (the Trends page), `food-sheets.js` (the sheet bodies) and
   `food-recipes.js` (recipes, saved meals, the coverage report).
4. **CSS per page**: `app.css` keeps tokens, base, controls, lists, sheets, navigation and the narrow
   phone rules; Today, Coach, Settings and Health, Goals and the lock screen move to their own files,
   linked straight after `app.css` in the same order, so the cascade does not change. Trends moves out
   of `food.css`.
5. **Server**: `src/ics.js` (the iCalendar parser, time zones and RRULE expansion) out of
   `calendar.js`; `src/health-parse.js` (units and the two export formats) out of `health.js`;
   `src/food-recipes.js` (saved meals, recipes, batches, plans) and `src/food-history.js` (Trends
   history and insights) out of `food.js`. Existing imports keep working through re-exports where
   tests and other modules use them.
6. **Later, not in this pass**: `motion.js` could give its gestures (sheet drag, swipe, pull) a module
   of their own, and `public/calendar.js` is a single page just over the line; both are left as they
   are. The Coach page is 20 px wider than a 402 px phone on `main` (seen while auditing); it is a
   layout bug, not a refactor, so it waits for its own fix.

## Rule from now on

Before a big launch or update, split any file over about 1,000 lines or mixing unrelated parts and
remove dead code, in a commit that changes no behaviour. It is in `README.md` and `CLAUDE.md`.

## Outcome (branch `v37/refactor`)

Done as planned, with three changes found on the way:

- The stylesheets are cut in their original order instead of moved page by page: Today's, Coach's and
  Goals' rules are overridden by the narrow-phone, sidebar and accessibility rules at the end of
  `app.css`, so moving a page's block later would have changed what wins. Consecutive cuts linked in
  the same order change nothing.
- `src/food.js` also gives up its schema (`src/food-schema.js`), and `src/calendar.js` its feed fetching
  (`src/calendar-fetch.js`), to come down near 1,000 lines.
- The server modules keep exporting what moved, so no caller or test changed.
